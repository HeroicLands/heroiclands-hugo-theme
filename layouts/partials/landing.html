{{- /* Package landing page. Six packages publish a landing at their own prefix — /sohl/, /thalorna/, /kethira/ and the rest (issue #33). Each one has the same job: say what the package is, say how to install it, and route the reader onward. Built separately they would not look like siblings, so the shape lives here and a package supplies only its own words and addresses. Rendered by `layouts/index.html` from the home page's front matter whenever that page declares `type: homepage` or carries a `landing` map, and by `layouts/landing/list.html` for a landing that is a *section* rather than the home page — a knowledgebase front page one level down, say. The whole contract is documented in README.md under "A package landing page"; the summary is: type "homepage" — what a package's `content/_index.md` declares to select this layout; "landing" on a section's `_index.md`. (page front matter) title Hero heading. (page front matter) description Hero standfirst. (page front matter) banner Hero image — resolved by hero-banner.html, so it obeys the same order and the same CDN indirection as every other banner on the site. With none set, that order lands on `images/banners/homepage.webp` for a `type: homepage` page, since the subtype default is keyed on the page's type. (page front matter) landing.lead Opening paragraph. landing.install.heading Heading above the install block. landing.install.intro Prose above the URL. landing.install.url The manifest URL, set to be read and copied. landing.install.note Prose below it — the required host version, where to report a fault. landing.cards.heading Heading above the card grid. landing.cards.source "sections" builds one card per section of the page being rendered. Omit to supply cards by hand. landing.cards.exclude Section names kept off a derived landing. landing.cards.banners true to give each derived card its section's own `banner:` as a card image. landing.cards.groups Derived cards gathered under headings. Each: `heading`, `sections` (the names it takes). landing.cards.items The cards. Each: `title`, optional `url` (makes the title a link), optional `description`, optional `banner` (a card image), optional `links` — each of those `title`, `url`, optional `note`. A card or link may carry `href` instead of `url` for an address that is already resolved against this site and must be used verbatim; that is what the derived mode fills in. landing.notices Standing notices — a licence carve-out, an attribution. Each: optional `title`, `body`. landing.closing Closing paragraph, centred. Every one of those is optional and every one is guarded: a package supplying a lead and an install block and nothing else renders those two and stops. A section with no data renders nothing at all rather than an empty heading or a gap, which is this theme's standing silent-disappear convention. Prose fields are rendered as **inline** markdown through `.RenderString`, so links and emphasis work in any of them and none of them can inject a stray block wrapper into the layout. A package with more to say than the contract carries writes it as the page body, which renders below the lead. The page is two bands, not five, so the vertical rhythm does not depend on which parts a package happens to supply: "what it is and how to get it", then "where to go next". */ -}} {{- $page := . -}} {{- $landing := .Params.landing | default dict -}} {{- $cards := $landing.cards | default dict -}} {{- /* The cards, resolved before anything renders, so an empty result can silently take the whole second band with it. */ -}} {{- $items := $cards.items | default slice -}} {{- $groups := $cards.groups | default slice -}} {{- $exclude := $cards.exclude | default slice -}} {{- $withBanners := $cards.banners | default false -}} {{- /* Derived from the sections of the page being rendered, so a content-driven package gains and loses a card as its build emits and retires one, with nobody having to remember. `$page.Sections`, not `$page.Site.Sections`: on a home page the two are the same list — Hugo defines the site's sections as the home page's — but a package that mounts its tree one level down (`kb/`, which is what `publish.address.prefix` produces) has exactly one top-level section, and deriving from it would render a single card pointing at the page the reader is already on. Reading the rendering page's own sections is the general case and leaves the home page's list untouched (issue #41). */ -}} {{- $derived := slice -}} {{- if eq ($cards.source | default "") "sections" -}} {{- range $page.Sections.ByTitle -}} {{- /* A section is named by the last segment of its address — the directory it is built from, which is the name the consumer's own configuration knows it by. */ -}} {{- $name := path.Base .RelPermalink -}} {{- if not (in $exclude $name) -}} {{- /* `href`, not `url`: a section's RelPermalink is already resolved against this site, prefix and all, and must not be resolved a second time. */ -}} {{- $derived = $derived | append (dict "name" $name "title" .Title "href" .RelPermalink "description" (.Params.description | default "") "banner" (cond $withBanners (.Params.banner | default "") "")) -}} {{- end -}} {{- end -}} {{- end -}} {{- /* Grouping is editorial and belongs to the page that publishes it: every card on a landing is a sibling section under the same mount, so nothing in the hierarchy distinguishes "Actors" from "Gear". A group therefore names the sections it takes, and anything it does not name still renders — in a plain row after the groups. That is the same gap-filling promise `_default/list.html` makes about orphaned pages: a section this landing has never been told about appears anyway, so a new content type is visible from the day it exists and can be filed into a group later. */ -}} {{- $leadCards := $items -}} {{- $groupBands := slice -}} {{- $restCards := slice -}} {{- if $groups -}} {{- $taken := slice -}} {{- range $groups -}} {{- $group := . -}} {{- $wanted := $group.sections | default slice -}} {{- $held := slice -}} {{- range $derived -}} {{- if in $wanted .name -}} {{- $held = $held | append . -}} {{- $taken = $taken | append .name -}} {{- end -}} {{- end -}} {{- with $held -}} {{- $groupBands = $groupBands | append (dict "heading" ($group.heading | default "") "cards" .) -}} {{- end -}} {{- end -}} {{- range $derived -}} {{- if not (in $taken .name) -}} {{- $restCards = $restCards | append . -}} {{- end -}} {{- end -}} {{- else -}} {{- /* No groups: authored cards render first and derived ones after, in one grid — which is what a landing without groups has always been. */ -}} {{- with $derived }}{{ $leadCards = $leadCards | append . }}{{ end -}} {{- end -}} {{- $anyCards := or $leadCards $groupBands $restCards -}} {{- partial "hero-banner.html" . -}} {{- if or $landing.lead $landing.install $page.Content }}
